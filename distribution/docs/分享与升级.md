# 分享与升级

## 怎样分享给别人

只发送经过校验的原始发布 ZIP、对应 SHA256 校验值以及这份文档。对方解压后配置自己的 QQ 与 API。不要把你已经用过的整个安装目录再次压缩发送：其中的 `config.json`、`state/`、`qq-bridge-runtime/`、`launcher-logs/` 都可能包含个人数据。

可通过 QQ 文件、网盘或自行创建的 GitHub Release 分享 ZIP。若公开源码，先按本包 `.gitignore` 排除运行数据，保留上游 MIT 许可与署名，并运行发布隐私校验；GitHub 历史中的凭据一旦泄露不能靠删文件补救，需要到服务商撤销。

发布包附有 `MANIFEST.json`（每个文件的 SHA256）与 `VERIFY-REPORT.json`。校验值用于发现文件变化，不代表第三方账号、平台许可或商业部署授权。

## 别人如何更新

1. 在旧包的启动菜单选择 2 停止服务，备份自己的完整旧目录，仅保存在自己设备。
2. 把新版本解压到新目录，先阅读版本说明，再完成新包初始化。
3. 迁移前确认新旧版本及 edition 一致；记忆数据库迁移只复制自己备份的 `qq-bridge/state/companion/` 等数据。不要用新包的空模板直接覆盖自己的运行配置，也不要把旧包的 node_modules、浏览器目录或整个 AI 运行环境搬进新包。
4. 核对管理员、白名单、模型、端口与功能开关，再启动。保留原备份直到确认消息与记忆正常。

Lite → Ultimate 需要语音可选依赖和自己的语音配置；Ultimate → Lite 不会支持旧语音开关，记忆主体仍可单独备份。两个版本都不带手机，更新不能自动获得模拟器能力。

## 包里有什么与没有什么

有：本项目源代码、依赖锁定清单、通用角色卡、启动器、本地向导、隔离的运行目录设计、费用保护与诊断工具。

没有：QQ/SnowLuma 本体或安装器、模拟器与ADB、原作者 API、私人角色卡/记忆/聊天、登录 Cookies、个人音色/RVC 模型、已经安装好的 node_modules 与 Python 环境。

第三方软件与 npm/Python 依赖在接收者本机按各自许可安装，不混进这份源码 ZIP。本项目的 MIT 许可仅覆盖适用的项目代码；保留包内 LICENSE 与上游来源说明。
